# Соглашение о качестве кода

Приоритеты PriceLab:

> Корректность → KISS → понятность → DRY → SOLID.

DRY и SOLID используются как подсказки, а не как цель рефакторинга.

## Правила

- Спецификация определяет поведение программы.
- Новая сущность или абстракция появляется только для уже существующей
  практической проблемы.
- Похожий код не объединяется, если после объединения его труднее понять.
- CLI и файловый ввод-вывод не смешиваются с расчётами без необходимости.
- Ошибки входных данных должны быть понятны пользователю.
- Рабочий `rates/params.yaml` не используется как фиксированный тестовый
  конфиг.

## Проверка

- Небольшие тесты проверяют отдельные правила и ошибки.
- Один эталонный Si-сценарий проверяет полный путь
  `check → candidates → adjust`.
- Ручная проверка подтверждает список кандидатов, участки до и после склеек и
  формат итогового MT5 TSV.

Изменение завершено, если оно связано со спецификацией, тесты проходят,
эталонный результат сохранён и новая архитектура не добавлена без нужды.
